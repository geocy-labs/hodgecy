# Node Ideals and Hilbert Functions

Blob 6 introduces the finite projective-scheme ideal layer needed before
classical defect computations.

## From Scheme to Hilbert Function

For a finite projective scheme

```text
Sigma in P^n
```

with homogeneous coordinate ring

```text
S = k[x0, ..., xn]
```

the homogeneous ideal is

```text
I_Sigma in S
```

and the coordinate ring is

```text
R_Sigma = S / I_Sigma.
```

The Hilbert function is

```text
H_Sigma(d) = dim_k (R_Sigma)_d
           = dim_k S_d - dim_k (I_Sigma)_d.
```

For standard projective space,

```text
dim_k S_d = binomial(n + d, n).
```

For a finite scheme of degree `N`, the Hilbert function is eventually `N`.
This eventual value is scheme-theoretic: a nonreduced scheme can also have
eventual Hilbert value equal to its degree.

## Ideal Sources

HodgeCY records how an ideal was obtained.

`JACOBIAN` ideals come from a hypersurface singular scheme, such as
`(F, dF/dx0, ..., dF/dxn)`, with the projective/saturation issues handled by
the producer of that ideal.

`EXPLICIT` ideals are homogeneous generators supplied by a dataset,
certificate, or supported exact computation.

`POINT_INTERSECTION` ideals are intersections of homogeneous ideals of exact
projective points. They may describe candidate support, complete support, or
certified support, depending on the upstream certificate. A point-set ideal is
not automatically the complete singular-scheme ideal.

`IMPORTED` ideals are accepted as externally supplied data with provenance;
importing an ideal is not the same as verifying it.

## Point Ideals

For a rational point

```text
p = [a0:...:an]
```

HodgeCY normalizes projective coordinates exactly. Equivalent inputs such as

```text
[1:2:3] and [2:4:6]
```

give the same point and the same homogeneous point ideal.

The point ideal is generated by the linear relations

```text
a_j x_i - a_i x_j
```

relative to a nonzero pivot coordinate. This is homogeneous and independent of
an affine chart choice.

## Groebner and Standard Monomials

Blob 6 computes exact Groebner bases over `QQ` for supported ideals. The
Hilbert function is then counted from the initial monomial ideal:

```text
H_{S/I}(d) = number of degree-d monomials not divisible by any leading monomial.
```

This is why the implementation stores:

```text
term order
backend
Groebner basis generators
leading monomials
ideal hash
```

The current backend is intentionally small and uses SymPy exact arithmetic over
`QQ`.

## Degree Is Not Enough

Two zero-dimensional schemes can have the same degree and different low-degree
Hilbert functions.

In `P^2`, three noncollinear reduced points have:

```text
H(0), H(1), H(2), ... = 1, 3, 3, ...
```

Three collinear reduced points have:

```text
H(0), H(1), H(2), ... = 1, 2, 3, ...
```

Both have degree `3`. The Hilbert function detects structure that degree alone
does not see. This is exactly the kind of refinement needed before HodgeCY can
study critical-degree defect.

## Reduced Versus Nonreduced

A doubled point can have degree `2` and support cardinality `1`. Its eventual
Hilbert value is `2`, but that does not imply reducedness. Blob 6 therefore
does not use Hilbert-degree consistency to promote reducedness claims.

